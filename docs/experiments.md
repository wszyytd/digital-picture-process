# 模型比较规范

## 初始比较对象

- 原始 YOLOv5 v7.0 的 YOLOv5n。
- 原始 YOLOv7 的 YOLOv7-tiny。
- Ultralytics 8.3.0 的 YOLOv8n。

这三个模型参数量和结构不同，不是严格等算力比较。记录参数量、资源使用、部署延迟与检测指标，以呈现实际精度/资源取舍。所有运行使用相同数据划分与类别映射。

## CPU 冒烟与正式实验

COCO8 只验证读数据、前向、反向、保存权重和推理是否能执行。官方预训练已使用 COCO，不得将 COCO8 高分视为泛化证据。本机 CPU 的耗时也不能代替服务器 GPU 或目标边缘设备耗时。

正式配置初始为 640 输入、50 epoch、batch 8、workers 4。根据显存确定 batch 后，为可比实验固定或记录其差异。三个实现的增强策略、损失和训练细节并不完全一样；当前是共享任务与预算下的官方实现比较，不是控制所有训练因素的架构消融。

YOLOv5/v8 显式设 seed=1；固定 YOLOv7 源码单进程的 init_seeds(2 + rank) 在 rank=-1 时也是 1。当前入口只承诺单进程 CPU/单 GPU；多 GPU 与多种子重复需要扩展并验证，不得把现有入口宣传为完整 DDP 支持。

v7-tiny 使用 hyp.scratch.tiny.yaml（含 tiny 适用损失配置）和 cfg/training/yolov7-tiny.yaml。v7 的验证打开 --v5-metric。独立 val 入口统一 conf=0.001 和 NMS IoU=0.6；各实现仍可能有细节差异，正式论文式比较应进一步采用共同 evaluator。入口暂不自动汇总三种格式的原始指标。

## 建议报告

检测：mAP50、mAP50-95、各类别 precision/recall、小目标与遮挡失败案例。

速度：同一设备，batch=1，固定图像尺寸和推理后端，预热后统计 P50/P95。说明是否包含预处理、后处理、数据传输和排队；CUDA 计时需要正确同步。训练日志中的速度不能直接当端到端延迟。

下游：固定 SLAM，比较无过滤、框过滤、深度细化过滤。记录 ATE/RPE、跟踪丢失与静态特征保留。检测器不直接预测世界坐标中的运动状态。

## 归档

每组保留原始日志、环境清单、上游 commit、主仓库 commit、数据版本、输入/输出权重、训练配置和失败案例。当前入口只生成实验记录，不自动完成检测标注质量审查或 SLAM 实验。
